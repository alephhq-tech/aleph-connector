# Errors and recovery

Read the error before retrying. Most failures leave the drawing untouched, but a timeout may not.

A failed tool call returns `isError: true` with `{ "error": { "code", "name", "message", "hint", "retryable" } }`. `hint` is the concrete next step; only retry the same call unchanged when `retryable` is `true` (AutoCAD was busy).

## Batch results

An `operations` → `apply` that fails does **not** raise an error — it returns `"status": "aborted"` with an `error`. Nothing from that batch was drawn. `error.code` is always `-32005 TransactionFailed` here; the actual cause is in `error.message`. The result's `error.hint` repeats the next step. Fix the cause and resend the whole batch.

## Timeouts

A timeout does **not** mean the change failed. AutoCAD may still run the queued work once it is idle again.

1. Ask the user to finish or cancel whatever is open in AutoCAD (dialog, running command).
2. Check what landed: `operations` → `history` (did a batch with your step count appear?) and `entity` → `list` on the affected layer.
3. Resend only what's missing. Never resend a mutation without checking — you will draw everything twice.

## Locked layers

Moving, erasing, or otherwise changing entities on a locked layer fails — as an aborted batch inside `operations.apply`, or a -32000 error for a single call. Ask the user before unlocking (`layer` → `set_properties` with `locked: false`), and lock it again afterwards if they want.

## Camera failures

`view` → `zoom`/`zoom_extents` never changes drawing data, so a `-32022` costs nothing — but don't loop on it either. The usual cause is a tab whose model space has never been displayed: AutoCAD reports a degenerate current view (zero width/height), which the plugin now repairs before fitting. If it still fails, the drawing's extents themselves are unusable (a stray object at an undefined coordinate) — the message says so.

- Verify the drawing by data, not by camera: `entity` → `list` (with `layer`/`kind` filters) and `drawing` → `info`.
- A `center` + `viewHeight` zoom that reports success but doesn't look right is not this error — the call now honors the requested height exactly.
- If the user can see the drawing, ask them to press Ctrl+0 (or ZOOM Extents) once in AutoCAD, then retry.
